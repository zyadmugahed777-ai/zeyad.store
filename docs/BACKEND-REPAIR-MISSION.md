# سياق مهام إصلاح وتطوير الباك إند (BACKEND REPAIR CONTEXT)
**مشروع:** زياد للتجارة (ZeyadStore)  
**الدور:** مهندس الإنتاج الرئيسي المستقل (Autonomous Lead Production Engineer)  
**المبدأ:**  
> *"This document provides context and observations regarding the backend codebase. Claude independently evaluates the system, identifies root causes, and decides the best architectural and implementation solutions."*

---

## 1. سياق وهدف العمل على الباك إند (Mission Context)

الهدف العام هو تحقيق **الصلابة والاستقرار الفني والأداء العالي لبيئة الإنتاج**، وضمان عمل كافة التدفقات بين الواجهة والخادم وقاعدة البيانات بسلاسة ودون أخطاء.

Claude مسؤول عن:
- فحص واكتشاف التناقضات الفعلية في الكود وسلوك الـ Runtime.
- اختيار أنسب الحلول الهندسية وإعادة الهيكلة الآمنة عند الحاجة.
- التأكد من سلامة الجلسات، تدفقات السلة، إتمام الطلبات، وأمان الـ API.

---

## 2. المسار الهندسي المقترح للحلول (Optimal Engineering Workflow)

المسار التالي هو منهجية مقترحة وموصى بها هندسياً، ويملك Claude مرونة تعديلها حسب متطلبات المهمة:

```
Understand (استيعاب السياق)
  └──> Investigate (الفحص الحي للواقع)
        └──> Identify Root Cause (تحديد السبب الجذري)
              └──> Evaluate Options (تقييم الخيارات المعمارية)
                    └──> Choose Best Solution (اختيار الحل الأفضل)
                          └──> Implement (التطبيق البرمجي)
                                └──> Test & Regression Check (الاختبار ومنع التراجع)
                                      └──> Verify (التحقق النهائي بالأدلة)
```

---

## 3. المشاكل المرصودة وسياق المجالات الفنية (Observed Problem Domains)

الملاحظات التالية تمثل `[FACT]` و `[RECOMMENDATION]` تم رصدها من فحص الكود الحالي، لتقديم السياق لـ Claude:

### أ) المصادقة وإدارة الجلسات (Authentication & Sessions)
- **`[FACT]` رصد الخلل:** في `backend/routes/api/auth.js`، يتم استدعاء دالة `customerRepo.findByPhone(cleanPhone)` بشكل متزامن، بينما تعيد دالة المستودع في PostgreSQL كائناً غير متزامن (`Promise`). هذا يسبب سلوكاً غير متوقع في قراءة معرف المستخدم `customer.id`.
- **مجال المعالجة لـ Claude:** حرية تحويل المعالجات إلى `async/await`، إعادة تنظيم معالجة الأخطاء، أو إعادة هيكلة منطق المصادقة بما يراه مناسباً.

### ب) فهرس البحث والكتالوج (Search Index & Catalog)
- **`[FACT]` رصد الخلل:** يعتمد البحث في `product-service.js` على ذاكرة تخزين مؤقت ومكتبة Fuse.js. في حال تعديل أو إضافة منتج من لوحة التحكم، يجب التأكد من تجديد الفهرس (`invalidateSearchCache`) لضمان ظهور المنتجات الجديدة فوراً في نتائج البحث للزبائن.
- **مجال المعالجة لـ Claude:** حرية اختيار آلية التخزين المؤقت، البحث الهجين، أو الربط المباشر مع استعلامات PostgreSQL Full-Text Search.

### ج) السلة والطلبات والحسابات المالية (Cart, Checkout & Finance)
- **`[FACT]` سياق الحسابات:** الحسابات المالية تعتمد على عملتين أساسيتين (SAR كعملة مرجعية، و YER كعملة العرض والمحليات بسعر صرف معتمد).
- **مجال المعالجة لـ Claude:** التحقق من دمج سلة الضيف مع سلة المستخدم، والتحقق من حساب الإجمالي والخصومات بدقة من الخادم داخل معاملات متماسكة.

### د) تكامل الـ API ومعالجة الأخطاء (API Parity & Error Handling)
- **`[FACT]` رصد الملاحظات:** بعض المسارات في `routes/api/` تختلف في هيكل إرجاع الأخطاء وحالات الـ Status Codes.
- **مجال المعالجة لـ Claude:** توحيد مخرجات الـ Endpoints بما يعزز تجربة المستخدم وسهولة استهلاك الـ API من الواجهة الأمامية.

## 4. حرية المعمارية والتنفيذ لـ Claude

- **لا يوجد قيد معماري مفروض:** إذا رأى Claude أن نمط Repositories الحالي يحتاج لتعديل، أو أن دمج بعض الخدمات أو فصلها هو الأنسب، فله كامل الصلاحية في ذلك.
- **الفيصل الوحيد:** هو صحة الحل بالأدلة، واجتياز الاختبارات، وعدم كسر وظائف النظام أو الإضرار ببيانات الإنتاج.
