# سياسة مزودي الذكاء الاصطناعي والتشفير (AI PROVIDER CONTEXT & SECURITY)
**مشروع:** زياد للتجارة (ZeyadStore)  
**الهدف:** توثيق تجريد مزودي الذكاء، متطلبات الأمان والتشفير، وإدارة الاستهلاك.

---

## 1. تجريد مزودي الذكاء الاصطناعي (Provider Abstraction Context)

`[FACT]` يدعم النظام حالياً تجريد المزودات عبر `backend/services/ai/providers.js`:
- يدعم بروتوكول **OpenAI-Compatible** (مثل OpenRouter, Groq, OpenAI, الخوادم المحلية).
- يدعم نماذج سريعة واقتصادية مثل `google/gemini-2.5-flash` و `openai/gpt-4o-mini`.
- `[RECOMMENDATION]`: يستطيع Claude تحسين أو إضافة محولات جديدة لمزودين آخرين طالما أنها تلتزم بواجهة الاستدعاء وعزل الأخطاء.

---

## 2. سياسة تشفير وحماية المفاتيح (Secret Encryption — Safety Rule)

1. **`[FACT]` التشفير الإلزامي لقاعدة البيانات:**
   - تُخزن مفاتيح الـ API في جداول الإعدادات مشفرة بخوارزمية **AES-256-CBC** عبر `backend/services/ai/crypto.js`.
2. **`[FACT]` حظر كشف المفاتيح (Zero Leaks):**
   - يُحظر تماماً كتابة أو طباعة مفاتيح الـ API في ملفات التوثيق، الـ Prompts، أو السجلات العامة.
   - في واجهات الإدارة يتم تمويه المفاتيح المخزنة بقناع مثل: `••••••••••••`.

---

## 3. فحص الاتصال وإدارة الأخطاء (Health Checks & Fallbacks)

- **`[FACT]` فحص الاتصال:** نقطة الاتصال `POST /admin/najm/test-connection` تتيح للمشرف فحص صحة الـ API Key وقياس زمن الاستجابة.
- **`[RECOMMENDATION]` ضبط المهلة (Timeout):** المهلة الافتراضية المقترحة هي 30 ثانية باستخدام `AbortController` لمنع تعليق السيرفر في حال بطء المزود الخارجي.
- **`[RECOMMENDATION]` استراتيجية الـ Fallback:** عند فشل المزود الخارجي لأي سبب، يتم الانتقال بسلاسة للبحث المحلي في قاعدة البيانات دون إيقاف خدمة الزبون.
